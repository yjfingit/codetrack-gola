## 架构信息通路分析

1. GOLA trunk -> CodeTrack：DINOv2 输出的 768 tokens 被拆为 `Z_RGB / X_RGB / Z_TIR / X_TIR / Z_on / D_TIR`；`X_TIR` 与原 GOLA head 输入一致，真实 LasHeR-10 sentinel 检查通过。`X_TIR` 是待恢复主流，`X_RGB` 是跨模态辅助流，四组模板经全局均值和 MLP 变成一个 template context。

2. ECC diagnosis：`X_TIR + X_RGB + template context + H_bar -> (C_obs,C_ref) -> syndrome s -> token error q`。`q` 同时控制 TopK、refiner residual、denoiser noise/write、memory reliability、template gate，是全架构的中心控制量。校准后信息不再点质量；接口消融 `q_to_refiner=6.967e-3`，是所有被测条件中影响最大者。

3. Motion：Kalman 预测输出 spatial map、uncertainty 和 Mahalanobis。spatial map 作为 refiner attention bias；map entropy+uncertainty 进入 denoiser；uncertainty/Mahalanobis 进入 TRC；uncertainty进入 template gate。中心化标准化后 motion->refiner 消融 `5.870e-4`，motion->denoiser `5.138e-4`，信息确实被消费。

4. Temporal memory：`reliability=1-q` 对当前搜索 token 加权池化，滚动 bank 经 TRC confidence 和 TGS 生成 prior tokens。refiner 既在 condition 中接收 pooled memory，又把全部 prior tokens 作为额外 K/V；denoiser 只接收 prior-token 均值。两条实测影响分别 `1.772e-5 / 1.840e-5`，非零但远弱于 q、aux、motion，当前最明显的交互瓶颈就在这里。

5. Sparse refiner：TopK(q) 选 32/256 tokens，H 图为每个 suspect 路由 8 个邻居；query 同时融合邻居、同位置 RGB、全局模板、memory 和 q，attention 再受 motion bias 调制；最后以 `q * sigmoid(gate) * up(context)` 只写回 suspect tokens。小 `up`+温和 gate 让身份近似与梯度传播不再由同一个极小标量承担。

6. Denoiser/completion：refiner context 只 scatter 到 suspect 行，RGB condition 覆盖全部 token；global syndrome、motion entropy/uncertainty、memory mean 与 mean-var completion 一起进入两步 cross-attention+FiLM，最终 write-back 仍由 q 选择性门控。`s_to_denoiser=7.954e-4`、meanvar recovery gradient `0.2534`，这两条路径有效。

7. Head/loss/gate：`X_final` 进入原 GOLA head；clean teacher 分支 detached 地提供 diagnosis/recovery target，同时 clean head loss仍训练 adapters。完整 criterion 实测 `Loss/diag, rec, gain, motion, align, trc, gate, pres` 全存在。Template gate 的 score 在 head 之后发布给下一帧；recovery-only probe 中 gate 梯度为 0 是预期，完整 criterion 中 gate 梯度为 `1.096e-1`。

判断：空间 ECC->refiner->denoiser->head 主链现在有非零信息、非零梯度和直接可拟合能力；但 temporal S4 训练输入尚不满足其状态假设，因此“整个时序模型具备有效学习能力”目前只能判为**部分成立**，不能判为正式可训练完成。

## 问题点与改进方向

1. **P0：S4 temporal 训练流程断裂。** `config/GOLA/dinov2/codetrack_temporal.yaml:3-10` 明确写明 consecutive clip sampler 与 sequence-boundary reset 未实现；实际 S4 仍是 `config/GOLA/codetrack_s4/config.yaml:84-100` 的 random Siamese pair sampler。这样上一随机样本的 Kalman/memory/previous-score 会进入下一无关样本。应先实现同序列连续 clip batch、每个 sequence boundary 调 `reset_sequence()`、传递合法 frame order/valid mask，再启动 S4；否则只可做 wiring smoke，不应报告 temporal tracking 收益。

2. **P0：真实训练中的 Kalman observation 可能一直缺失。** `codetrack/criteria.py:562-570` 记录 runner 把 box 放在 targets、模型 forward 收不到它；因此 motion loss 能训练 prior map，但 filter state 未必得到逐帧 observation。sequence runner 应把当前 GT box/image size 作为延迟 observation 送入模型，严格保持 `predict(t) -> consume(t) -> observe(t)`。

3. **P1：首次校准在 DDP 下需要同步。** 当前每个 rank 在自己的首批 forward 内原地设置 gain/offset；不同首批会造成 rank 间参数起点不一致。建议在 DDP wrap 前用固定 train-only calibration batch，或对 raw mean/std 做 all-reduce 后一次性广播，再保存 checkpoint。

4. **P1：memory 是最弱接口。** 两条输出消融仅约 `1.8e-5`，比 q->refiner 小约 390 倍。优先在合法 clip 数据上检查 TRC confidence 分布、prior-token attention mass 和 admission ratio；denoiser 不要只取 prior-token mean，可保留 token set 做 cross-attention；需要跨帧信用分配时采用有限长度 TBPTT，而不是永久 detached bank。

5. **P2：template spatial 信息被全局均值抹平。** 四组模板的 256 个 token 被压为单个 `(B,768)` 向量，对所有 suspect 相同；当前 template->refiner 消融 `3.405e-4`，有效但弱。可保留 template tokens/foreground mask，以 suspect query 对 template 做位置或内容 cross-attention。

6. **P2：hard TopK 是离散瓶颈。** q 的值可反传，但索引选择不可微；训练早期 routing 错误只能主要靠 `L_diag` 间接修正。建议训练时用 soft/straight-through TopK 或在 TopK 外加 ranking/coverage loss，评估时仍保持 32-token hard budget。

7. **P2：template gate 的训练信号与真实漂移不完全对齐。** 当前 gate 主要由 synthetic corruption trust 标签监督，而且 random-pair S4 下 previous score 属于无关样本。合法 clip 数据上应使用当前 frame 的 head quality、GT IoU/visibility 与长期漂移结果构造 gate target，并分别报告 update precision/recall 与最终 SR(AUC)。

8. **P3：capacity 不等于泛化。** 当前 probe 证明“能优化固定 batch”，没有证明正式 tracking 提升。完成 P0 后应以 LasHeR train-dev 做短训并监控 `q AUROC/AUPRC、d_input/d_after、memory admission、template update precision/recall`，最后在独立 test 上报告官方 SR(AUC)，避免把 fixed-batch recovery 当闭环跟踪结果。
