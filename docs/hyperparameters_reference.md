# CodeTrack 超参数推荐值与理由（逐项）

**标注约定** —— 每个推荐值都注明依据类型，请按依据强度校准信任：

| 标记 | 含义 |
|---|---|
| **[实测]** | 在本机跑过对照实验/探针，有数字 |
| **[推导]** | 由维数守恒或数学性质推出，不是经验值 |
| **[文献]** | 来自论文消融数值或官方实现 |
| **[上游]** | 沿用 GOLA 官方配方 |
| **[判断]** | 我的工程判断，**未经实验验证** |

配套文档：`hyperparameters.md`（按"待决策程度"分层的清单）、`implementation.md`（实现记录）。

## 1. 输入与 token 布局（不可调）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `z_len` | **64** | **[推导]** | GOLA 官方 `template_size=[112,112]`、patch=14 → `112/14=8` → 8×8=64。改它即与预训练权重和 head 的 `map_size` 不一致 |
| `x_len` | **256** | **[推导]** | `search_region_size=[224,224]` → `224/14=16` → 16×16=256 |
| `dim` | **768** | **[推导]** | DINOv2 ViT-B/14 嵌入维；也是 `W_x: 768→mid_dim` 的定义域 |
| `grid` | **16** | **[推导]** | `sqrt(256)`；`config.validate()` 强制 `x_len == grid²`，因为 `_search_target_mask` 与运动先验图都按方形网格栅格化 |

> 四项共同决定 `F_L (B,768,768)` 的切片边界。改任一项都会让 `X_t` 不再等于上游 head 的输入，破坏初始化恒等性。

## 2. 校验矩阵 H（ECC 图结构）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `num_checks` (M) | **64** | **[推导]**+**[判断]** | 与 `d_c=12` 绑定：`M·d_c` 必须等于 `N·d_v = 256×3 = 768`，故 `M = 768/12 = 64` 是少数能整数平衡的取值。另：`M=16` 时每 check 覆盖 48 个 token，syndrome 分辨率太粗，会退化成全局置信度 |
| `h_links_per_check` (d_c) | **12** | **[推导]** | `768/M = 12`。它同时是行归一化分母，改它等于改 syndrome 尺度 |
| `h_min_col_degree` (d_v) | **3** | **[推导]**+**[文献]** | 守恒式 `N·d_v = M·d_c` 要求 d_v=3；架构图亦标 `d_v≈3`。**它还决定"一个坏 token 能触发几个 check"**：太小则该 token 可能不被任何 check 覆盖（无法定位），太大则定位分辨率下降 |
| `h_locality_window` | **5** | **[判断]** | `half = 5//2 = 2` → 5×5=25 个候选。要抽 `12−3=9` 条局部边，25 个候选留有余量；窗口=3（9 候选）几乎无选择余地，窗口=9（81 候选）局部性太弱。**建议消融 {3,5,7}** |
| `h_free_edge_frac` | **0.25** | **[实测]** | 实测三档产生的边集**几乎不重叠**（重叠仅 35–43/768），check 监视跨度 **10.7 / 12.4 / 13.5** 格。0.25 = 每 check「9 条局部边 + 3 条全局边」：纯局部(0.0)会让远离任何 check 中心的 token 难被覆盖，纯随机(1.0)则失去"syndrome 即地址"的性质。**留 1/4 全局边是连通性兜底**。建议消融 {0.0, 0.25, 0.5} |
| `h_locality_wrap` | **True** | **[判断]** | 网格边界环绕，使边缘 check 的候选池与中心 check 一样大（否则角落 5×5 窗口只有 9 个 token，恰好等于所需局部边数，退化为确定性选择） |
| `h_seed` | **1234** | **[判断]** | 支撑矩阵必须确定性可复现——它是 `persistent=False` buffer，加载时靠此种子重建。改它等于换一套 H |

## 3. 错误诊断（syndrome → q）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `mid_dim` | **128** | **[文献]** | 架构图 3.1 标「768→128」。把 check 空间计算量压到 1/6，同时保住足够通道承载 obs/ref 差异 |
| `syndrome_hidden` | **128** | **[判断]** | `mlp_s` 输入 `2×mid_dim = 256` 维、输出 1 维，128 隐层足够；check 数（64）才是信息瓶颈 |
| `syndrome_cos` | **True** | **[文献]** | 架构图 3.1 明确列 `Δ`、`|Δ|`、`cos` 三项。`cos` 是**尺度不变**的方向一致性——两模态整体亮度不同时 `Δ` 的幅度会误导，`cos` 不会 |
| `detection_prior` | **0.2** | **[文献]**+**[实测]** | 它是 `vote_bias` 的 `logit(0.2)` 初始化。取 0.2 与 corruption 配比一致；**更关键是不要用 0**：0 偏置起步概率 0.5、soft-BCE 恰为 `ln2 = 0.693`，而目标密度 0.2 相距 2.7 个 logit，head 会花整个训练反学自己的初始化。参考工程有实测记录：0 偏置 soft-BCE 0.6932 **还不如**预测常数的 0.6534 |

## 4. 运动先验（Kalman）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `motion_enabled` | **True** | **[文献]** | DTPTrack Table 6 的关键教训：**运动必须作为特征输入**（注意力偏置 + 门控输入），不能作为运动模型的输出替代时序聚合。手写运动先验（momentum 73.8 / optical flow 73.2）替换学习式 TGS 会掉点（vs 74.3） |
| `motion_process_noise` (Q) | **1e-2** | **[判断]** | 与 `P0` 的位置项（`1e-2`）同量级，使预测步在匀速假设下不会过快膨胀协方差。坐标是归一化的，故跨序列通用 |
| `motion_measurement_noise` (R) | **4e-2** | **[判断]** | 归一化框的位置误差量级约 1e-2~1e-1，R=4e-2 使 `K=P/(P+R)` 在稳速时给出温和增益。**R 还会被 `box_confidence` 动态膨胀**（`R·(1+20(1−conf))`）——低置信观测自动降权，这是防止"GT 框直接主导"的设计 |
| `motion_gate_hidden` | **64** | **[判断]** | 先验头输入 `8(状态)+8(diag std)+1(u_t)=17` 维、输出 1 维，两层 64 足够（末层零初始化） |
| `motion_state_dim` | **8** | **[判断]** | `[cx,cy,w,h,vx,vy,vw,vh]`。**理论上高宽宜用 `log w, log h`**（尺度变化是乘性的），但当前实现对宽高走线性 A，日志版本未实现——**已知简化**，见文末"已知不足" |

> **Q 与 R 的比值才是真正影响行为的量**（决定卡尔曼增益），等比例缩放无影响。要调只调比值。

## 5. 时序记忆（TRC + TGS，依据 DTPTrack）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `memory_enabled` | **True** | **[文献]** | DTPTrack Table 5：TRC/TGS 相比"同等帧数但无该模块"的基线 **+1.0 AUC** |
| `memory_frames` | **3** | **[文献]**+**[判断]** | 架构图给 3~4。DTPTrack Table 7：3 帧 73.2 → 4 帧 73.7 → 5 帧 74.3（单调，但**该表首行"2 帧"与另一表数值相同，疑为论文笔误，不可引用**）。取 3 是显存与收益的折中：我们已有双分支前向（clean teacher + corrupted student），再加参考帧开销显著上升。**Stage 2 成功后再试 4** |
| `memory_tokens` (K) | **8** | **[文献]**+**[判断]** | 架构图 `B×K×8×128`。DTPTrack 的 K 实际硬编码为 provider 帧数（=4），论文只说"small hyperparameter"。取 8 是因为这些 prior tokens 要承载**两个模态 + 多个历史帧**的压缩信息，比 DTPTrack 的单模态单帧需要更大容量 |
| `memory_dim` | **128** | **[文献]** | 架构图 `8×128`；128 也是 refiner/denoiser 的瓶颈宽度，保持全链路一致 |
| `admission_threshold` | **0.85** | **[文献]**+**[实测]** | DTPTrack **代码**里的 `update_criteria: 0.85`（论文完全没提，却承担大量漂移控制）。实测准入按预期工作（分数 0.1 被拒、0.99 被接纳，返回 `[False, True]`）。**不设阈值 = 让被污染帧进入记忆库，正是要解决的问题** |
| `decay` | **0.6** | **[判断]** | 记忆库滚动时的年龄衰减。0.6 使 3 帧后权重降到 0.22——近期优先但不完全丢弃历史。**这不是 DTPTrack 的机制**（它靠 TRC 门控而非时间衰减），是我们的补充 |

> TRC 门控与 base prior 都是**可学习**的，所以没有需要手设的门控强度参数。依据：DTPTrack 把**学习式门控换成静态阈值 −2.3 AUC**（Table 5a）、**去掉可学习 base prior −1.6**（Table 5c）。

## 6. 选择性恢复（TopK + H 路由）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `topk_tokens` (K) | **32** | **[文献]**+**[推导]** | 架构图 `K ≤ 32，≤12.5%`。**12.5% 有实际含义**：corruption 配比里 token 级破坏率约 `0.33×0.4 ≈ 13%`，所以 12.5% 预算刚好覆盖真实需修复量并留余量。取 64（25%）会把健康 token 也拖进修正，违背"选择性"这一核心主张 |
| `num_neighbours` (K_n) | **8** | **[文献]** | 架构图 `K_n = 8`。**上界由 H 列度决定**：每 token 只被 3 个 check 监视，`H^T H` 的非零邻居有限；8 是"共享校验的 token 里挑最相关的 8 个" |
| `refiner_hidden` | **256** | **[文献]** | 架构图「768→256→768」，3× 压缩 |
| `refiner_heads` | **4** | **[判断]** | `256/4 = 64` 维每头；K/V 只有 8 个邻居，头数再多无额外信息可分流。`d_k=64` 也是常见稳定配置 |
| `refiner_dropout` | **0.0** | **[判断]** | 该模块只在 32/256 token 上激活，本身已是极强稀疏正则；再加 dropout 会与"修正量必须精确"冲突 |
| `residual_gate_init` | **−8.0** | **[实测]** | **全代码最关键的数值参数**。残差以 `sigmoid(gate)·delta` 写回，一个标量同时控制①stage-0 与基线的接近度②整个分支的梯度可达性。实测：<br>· −12 → sigmoid 6.1e-6，到达时序记忆的梯度 **3.1e-7**（名义连通但训不动）<br>· **−8 → sigmoid 3.4e-4，梯度 1.9e-5（50×）**，stage-0 输出与基线仍只差 ~2.4e-6<br>· −4 → sigmoid 1.8e-2，相对恒等性偏差过大<br>**教训**：零初始化输出层更糟（`up.weight=0 ⇒ ∂/∂上游 ∝ 0`，梯度恒为零） |
| `motion_bias_scale` | **0.5** | **[判断]** | `attn_bias = log(M_t)·scale`。`log` 后动态范围很大（`M_t∈[0,1]`，已 clamp 到 −9.2），乘 0.5 后单头 logits 偏移约 ±4.6，与注意力 logits 本身量级相当——**"轻推"而非主导**。取 1.0/2.0 会让运动先验压过内容相似度，退化成运动跟踪器 |

## 7. 去噪修正（SCDT 式迭代精修）

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `diffusion_enabled` | **True** | **[文献]** | SCDT 消融：`L_align + L_recon`（77.4/61.0）优于单用任一（76.0/59.9、75.6/59.5） |
| `diffusion_steps` | **2** | **[文献]**+**[方案红线]** | **硬约束：不做 20–100 步 DDPM**（tracker 跑不起）。2 步是"精修"而非"生成"。MaskGIT 证明少量迭代 refinement 比长自回归更高效 |
| `diffusion_hidden` | **256** | **[判断]** | 与 refiner 一致。**这是当前参数量的主要来源**（denoiser 约 1.4M）：它要对全部 256 个 token 做 cross-attention，宽度直接乘在 token 数上。要压 CodeTrack 参数量（当前 10.03M vs 架构图估 2–3M），**首选降到 128** |
| `diffusion_heads` | **4** | **[判断]** | 同 refiner |
| `noise_weak_std` | **0.05** | **[判断]** | SCDT 的"weak noise"。只给**被判坏**的 token（`1−alpha` 加权）加噪，应远小于特征自身 std（≈1）。0.05 ≈ 5% |
| `noise_strong_std` | **0.20** | **[判断]** | "strong noise"，约 4× weak。两者太接近则 `noise_strong_prob` 失去意义 |
| `noise_strong_prob` | **0.5** | **[判断]** | 每步各 50% 概率强弱二选一，让模型同时见到两种退化档位，避免对某一档过拟合 |
| `noise_schedule_power` | **1.0** | **[实测]** | `alpha_bar = cos(π/2·(t/T)^u)`，u=1、T=2 → `[1.0, 0.001]`。残差权重 `(1−ab)` = `[0, 0.999]`：第一步在接近原始被污染特征上工作，第二步几乎完全信任自身预测。配合 `sigmoid(−8)` 输出门，整体是**先保守后激进**，符合"先诊断定位、再集中修复" |
| `residual_clip` | **0.0**（不裁剪） | **[判断]** | 暂未启用。若 Stage 2 出现修复量爆炸（`delta` 范数远超 `X_t` 范数），设为 `≈‖X_t‖` 的 1–2 倍 |

## 8. 模板保护

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `template_protection` | **True** | **[文献]** | 官方 GOLA ablation 显示 online template 很重要，而 update 规则仅 `score > 0.84`——**这正是错误传播的入口**（被污染帧的 appearance 被烤进模板） |
| `gola_update_threshold` | **0.84** | **[上游]**+**[实测]** | 官方 `run.yaml` 的 `update_threshold: 0.84`，已在源码核对。**不要改**：改了会让评测行为偏离官方 updater，baseline 不可比 |
| `template_threshold` (τ_c) | **0.5** | **[判断]** | `c_t` 的 sigmoid 自然分界。配合 `init_bias=−1.0`（起步 c≈0.27，保守），含义是"默认拒绝更新，须靠证据把 c_t 推过 0.5 才允许"。设成 0.7 会让起步阶段几乎永不更新，浪费 online template 的收益 |
| `template_gate_hidden` | **64** | **[判断]** | 输入 5 维、输出 1 维，64 已远超所需 |
| `template_gate` init_bias | **−1.0** | **[实测]** | 参考工程有完全同型的失败记录：syndrome head 用 0 偏置起步时 soft-BCE 卡在 `ln2`，**不如预测常数**。这里同理——`+2.0` 起步 c≈0.88 会让 sigmoid 饱和、梯度消失，门控花整个训练反学自己的初始化。−1.0 起步 c≈0.27，是"最坏情况（官方 updater 全接纳）"与"最保守"之间的中点 |

## 9. 损失权重

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `w_track_corr` | **1.0** | **[文献]** | 架构图 Loss 面板首项，**主角**。它是唯一能保证"修复后特征对跟踪任务有用"的信号 |
| `w_track_clean` | **0.25** | **[文献]** | 架构图给定。作用是**正则**：防止 GOLA 原有能力为适配合成 corruption 而退化（风险 #6）。25% 足以约束而不稀释主任务 |
| `lambda_diag` | **0.5** | **[文献]** | 方案文档 §15 给定。诊断是中间量、无直接任务收益，靠自身收敛不够；但也不能喧宾夺主 |
| `lambda_rec` | **0.2** | **[文献]**+**[判断]** | 方案给 0.2–0.3，**取下沿**。风险 #2 就是"重建变好但 SR 不涨"，此时唯一应对是降 `lambda_rec`；从下沿起步意味着**有下调空间**，若一开始取 0.3 再发现要降等于白跑一轮 |
| `lambda_align` | **0.2** | **[文献]** | SCDT 的 `L_align` 单独就有 76.0/59.9，与 `L_recon` 组合到 77.4/61.0。它比逐元素重建**更便宜也更鲁棒**（只约束一阶二阶统计量） |
| `lambda_pres` | **0.01** | **[判断]** | 代码层已对可靠 token 做**严格 identity bypass**（`X_final[keep] = X_t[keep]`，是赋值不是损失），故此项近乎冗余，留作数值兜底。**可安全设为 0** |
| `lambda_mem` | **0.1** | **[判断]**+**[实测]** | `L_mem` 是记忆可靠性头**唯一**的监督；没有它可靠性分数无人训练、退化为常数。**这也是修掉的一个 bug**：`config.py` 原默认 `0.0`，YAML 未显式给值时该监督会被静默关闭 |
| `lambda_gate` | **0.1** | **[实测]** | 同理，`L_gate` 是模板门控参数的唯一梯度来源（实测：不加它时门控梯度为 **0**——主跟踪损失的输出路径被 `sigmoid(−8)` 压掉了 5 个数量级） |
| `lambda_motion` | **0.2** | **[实测]** | **[注意]** 单序列上实测恒为 0：Kalman 观测到 GT 框后预测的高斯与监督目标**按构造相同**，KL 恒为零。需连续序列递推训练才非退化。保留 0.2 是为在正式训练中让先验头学到"何时该修正先验" |
| `diagnosis_alpha` | **0.5** | **[文献]** | 方案文档 §5.5 第一版取值：`e* = 0.5·e_feat + 0.5·e_task`。**这是"不用 corruption mask 当唯一目标"的执行方式**。建议消融 {0.3, 0.5, 0.7} |

## 10. Corruption 课程

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| `corruption_enabled` | **True** | **[文献]** | 没有 corruption 就没有可诊断的错误，诊断头会退化成常数 |
| `corruption_image_prob` | **0.45** | **[文献]** | 方案配比"图像级 45%"。**注意：当前实现把它复用为 token 级触发率**（见文末局限） |
| `corruption_token_ratio` | **0.4** | **[文献]** | 方案配比：被擦除/加噪的 patch 占搜索网格 40%。**远大于 K=32（12.5%）是故意的**——训练时制造超过修复预算的破坏，才能检验"选择性"是否真在挑最该修的 token，而非"刚好修完全部" |
| `corruption_severity` | **0.4** | **[文献]** | 方案配比。建议配合 curriculum **递增**（如 0.2→0.6），先易后难 |
| corruption 类型集合 | 5 图像 + 4 token | **[文献]** | 图像：`low_light / over_exposure / gaussian_noise / blur / occlusion`；token：`block_erase / burst_erase / feat_noise / modality_drop`（方案文档 §11.3 清单） |

## 11. 训练超参

| 参数 | 推荐 | 依据 | 理由 |
|---|---:|---|---|
| optimizer | **AdamW** | **[上游]** | GOLA 官方配方 |

### 分组学习率 —— **最需要拍板的一项**

当前框架只有一个 `lr: 1e-4` 作用于所有可训练参数，**与方案文档 §10.3 冲突**：

| 参数组 | 推荐 LR | 依据 | 理由 |
|---|---:|---|---|
| CodeTrack（diagnosis/recovery/denoiser/gate/memory） | **1e-4** | **[判断]** | 全部随机初始化，需最大步长快速进入有效区间；与官方 `lr` 一致，不必额外调 |
| GOLA low-rank (`lora.GA`/`lora.GB`) | **2.5e-5** | **[文献]**+**[判断]** | 方案给 2e-5~3e-5，取中值。GOLA 已是收敛良好的 checkpoint，用 1e-4 会把它推离原解 |
| token-type embedding | **2.5e-5** | **[判断]** | 同上，属 GOLA 已训练参数 |
| 原 GOLA head | **1e-5** | **[判断]** | head 决策面已很准，且它直接吃 `X_final`，**在合成 corruption 上最容易漂移**，故给 GOLA 侧最小学习率 |
| Stage-3 DINO last-2 blocks（可选） | **1.5e-6** | **[文献]** | 方案给 1e-6~2e-6，取中值。必须满足 `lr_DINO ≪ lr_GOLA ≪ lr_CodeTrack` |

框架 `optimizer.per_parameter` + `name_regex` 支持按组设 `lr`，可直接实现。**这是我认为最高优先级的一项**：head 用 1e-4 在合成 corruption 上漂移会同时损害 clean 与 robust 指标。

## 12. 分阶段推荐

| Stage | 训练范围 | LR | steps | micro_batch |
|---|---|---|---|---|
| 0 复现 | 不训练 | — | — | — |
| 1 稳定化 | 仅 Diagnosis + Refiner，GOLA 冻结 | 1e-4 | 500–1000 | 16 |
| 2 主训练 | GOLA adapters + head + CodeTrack | **分组**（§11） | 6000–8000 | 8 |
| 3 可选 | + DINO last-2 blocks | DINO 1.5e-6 | 1500–2000 | 8 |
| 4 时序 | + KF / memory / protection，改 causal clip | 同 Stage 2 | — | 8 |

**Stage 1 冻结 GOLA 是 warm-up，不违反"必须联合训练"的硬约束**——它不是最终模型。目的是先让随机初始化的诊断/恢复模块进入有效区间，避免其噪声梯度在早期污染 GOLA adapter（风险 #6）。

## 13. 已知不足与后续优先级

### 已知不足（如实列出）

1. **图像级 corruption 是死代码**。我核查了调用路径：`CorruptionSchedule.draw_image()` 与 `corrupt_image()` **在当前模型中从未被调用**，也未接进数据 collator。目前只有 token(级) corruption 生效；且 `corruption_image_prob=0.45` 被 `draw_token()` 复用为触发率，实际为 `(1−0.45)×0.6 = 0.33`。等效 batch 配比约 **clean 67% / token 33% / 图像级 0%**，与方案的 **30/45/20/5** 差距很大。
2. **`L_motion` 在单序列上恒为 0**（KL 恒零，见 §9）。
3. **`motion_state_dim` 的宽高未用对数参数化**（§4）。
4. **CodeTrack 参数量 10.03M > 架构图估计 2–3M**，主因是 denoiser（§7）。
5. **分组学习率未实现**（§11）。
6. 所有非"**[实测]**/[推导]"的参数**都还没有性能消融**——它们目前是"有理由的起点"，不是"调优结果"。

### 优先级

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | 实现分组学习率 | 当前与方案冲突；head 漂移同时伤 clean 与 robust |
| **P0** | 接上图像级 corruption（collator 插件） | 当前是死代码；缺它则三层验证协议里的 "Natural" 无从谈起 |
| **P1** | 连续序列（causal clip）训练 | `L_motion` 恒零；memory 的时序语义也需真序列 |
| **P1** | 消融 `h_free_edge_frac` ∈ {0, 0.25, 0.5} | H3 图结构消融核心，直接检验"H 路由 vs 空间 kNN"（风险 #3） |
| **P2** | 消融 `lambda_rec` ∈ {0, 0.1, 0.25, 0.5} | 风险 #2 的唯一旋钮 |
| **P2** | 试 `memory_frames=4` | DTPTrack Table 7 单调增益；先确认显存 |
| **P3** | 压 `diffusion_hidden` 到 128 | CodeTrack 参数量的主要来源 |
