# 按训练帧覆盖的 20 轮配方（2026-10-08）

本记录取代旧 README 中的三卡、每视频随机采样 16 次和每轮验证设置。当前默认采样器是 `frame_coverage`，使用物理 GPU 3/4 的两卡 DDP。旧运行已经停止，权重与日志保留；新配方通过覆盖规划和两卡短试跑后，已启动 `outputs/causal20_coverage_2gpu_20261008` 中的完整 20 轮训练；两个 rank 和首批有限损失已确认，完整训练尚未完成。

## 数据范围

LasHeR-train 共 979 段视频、514,081 个 RGB-T 帧对。沿用已固定且不重叠的 881/98 视频划分：

- 训练：881 段、450,520 个帧对。
- 验证：98 段、63,561 个帧对，只在完成第 4/8/12/16/20 轮后做完整验证。
- 每段训练视频的第 0 帧用于初始化，其余 **449,639 个搜索帧每轮全部安排进入训练**。其中 1,477 帧的框标注无效，保留时间顺序、屏蔽框回归，并按现有目标生成器作为无目标分类样本；有效框搜索帧共 448,162 个。

不把验证视频加入梯度训练，也不读取 LasHeR-test 来修改配方。历史上已有部分 test 暴露，不能宣称测试集从未接触。

## 覆盖方法

先为每段视频列出完整窗口清单，再全局打乱窗口顺序，最后分配给两卡。视频越长，分配到的窗口越多。每个窗口的初始化标注严格来自搜索起点之前的有效帧；当前帧标注只作为损失目标。每个 clip 重置 motion/memory，clip 内保持时间顺序。

| 轮次 | 每窗口搜索帧数 | 每卡窗口数/批 | 每轮窗口数（不含 DDP 补齐） | 每轮独立搜索帧 | 每轮参数更新数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1–4 | 1 | 16 | 449,639 | 449,639 | 14,052 |
| 5–12 | 8 | 4 | 56,575 | 449,639 | 14,144 |
| 13–20 | 16 | 4 | 28,498 | 449,639 | 14,252 |

末尾不足完整窗口时，把最后一个窗口向前移动，允许少量重叠，不丢掉尾帧，不复制主监督帧凑长度。本数据集所有训练视频均足够容纳 16 帧搜索窗口。

未来收益标签额外需要最多 3 张未来图。视频末尾不存在的未来位置通过显式 mask 排除；不能用复制最后一帧伪造完整四帧收益或 commit 标签。空间阶段不训练四帧收益目标。

两卡全局补齐分别仅增加 25/1/6 个窗口，使各 rank 的 batch 和更新次数相同，无丢弃样本。含末尾重叠与 DDP 补齐，每轮搜索帧呈现次数分别为 449,664 / 452,608 / 456,064。

## 学习设置

沿用空间→8 帧→16 帧课程、TBPTT=4 和渐进使用历史预测。DINOv2 冻结，LoRA、GOLA head 与 CodeTrack 模块可训练。沿用 BF16、AdamW、权重衰减、dropout、梯度裁剪和损失项；数据增强为整段共享的水平翻转与亮度增益，尚未把早期计划中所有高级增强都实现。

每阶段第一批检查各可训练模块梯度；每步检查有限损失与梯度。每卡连续 clip batch 保持 4，不增加到 8。DataLoader 为 8 workers、pinned memory、persistent workers、prefetch_factor=4。

20 轮共 **283,376 次参数更新**，按此重新计算 5% warmup（14,169 次更新）与余弦衰减。旧随机采样配方为 86,340 次更新；更新数比例约 3.28，因阶段成本和 I/O 不同，不能直接把它当成实际耗时比例。完整耗时需要分别测量三阶段持续吞吐和完整验证耗时。

## 覆盖证据与保存

计划保存在 `outputs/causal20_coverage_plan_20261008/`，含长度 1/8/16 的 `.npz` 清单、每视频覆盖计数、标注 SHA256 和计划 SHA256。正式运行另将相同计划写入自己的 `coverage/` 目录。

每轮训练结束，各 rank 保存实际消费的窗口 ID 和观测统计。rank 0 合并后，必须与完整计划 ID 集合完全一致，才允许保存该轮 checkpoint。记录区分：

1. **计划覆盖**：全部搜索帧列入清单。
2. **实际消费覆盖**：实际走完所有窗口并完成更新。
3. **目标在裁剪图中的可见性**：历史预测裁剪可能把目标裁出画面，另计 `valid_without_positive_grid_cells`。读取了原图不等于目标一定在有效裁剪中。

每轮保存完整权重、optimizer、scheduler、各 rank 随机状态、配置和序列 manifest，保留全部 20 轮。采样与 scheduler 预算改变后，旧随机配方的 checkpoint 不支持原样续跑；新配方应在新输出目录从基线开始，不能把旧轮次计入新 20 轮。

## 验证结果

- `tools/verify_frame_coverage.py`：5 个 CPU 测试通过，覆盖尾部余数、长无效标注段、两卡等长分片及完整并集、未来 mask、标注指纹。
- `outputs/causal20_checks/smoke_coverage_20261008.log`：真实 GPU 3/4 三阶段参数更新通过。
- `outputs/causal20_checks/smoke_coverage_tail_20261008.log`：专门抽取视频尾部，真实两卡三阶段参数更新通过；各可训练模块梯度有限且非零，峰值 allocated 约 7.91 / 8.84 / 9.25 GiB。
- 尾部试跑的 8 帧阶段共训练 64 个搜索观测，只有 40 个拥有完整四帧未来监督；16 帧阶段为 128/104，符合每窗口最后 3 个位置屏蔽的预期。
- 试跑清单明确记为 `smoke: true, complete: false`，不计为全量完成一轮。
- Python 编译、shell 语法、`git diff --check` 和面板快照通过。

这些检查证明覆盖逻辑与短程执行可用，尚不能证明全程稳定、收敛或超过 GOLA-B。
